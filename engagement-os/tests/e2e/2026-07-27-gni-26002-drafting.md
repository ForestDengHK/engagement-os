# E2E — GNI 26-002 **drafting** leg against the real tender pack (2026-07-27)

**What we did:** picked up `~/working/gni-26002-v4` — a pursuit repo whose analysis leg was already
run (69-row compliance matrix, RFP analysis, reuse analysis, formula-live estimate, 16-asset index)
and whose `3_drafting/` was empty — and ran the drafting leg the way a user would: research the
gaps → build the section map → draft Volume 2 §5.1.1–§5.1.4 → build the figures → review rounds →
strict check → render → measure. Then compared the result against the original manually-written GNI
26-002 Volume 2 (`~/working/gni/01_rfp/26-002/4_final/`) — **the bid we actually won**.

**Why this leg:** the July-26 E2E stopped at two blocked sections and proved only that the render
gate *refuses*. Everything that decides whether a response scores — the 28%-weighted Deliverables
section with its per-item scoring, the shared page budget, the figure pipeline, iterated review
rounds, and the page count of the real submission form — had never been exercised.

## Bugs found by running the flow (all fixed same-day)

| # | Bug | Found by | Fix |
|---|---|---|---|
| 1 | **The render gate missed the `[⚠VERIFY]` form the pack itself writes.** The bid profile matched the bare literal `"[⚠VERIFY]"`, but every real marker carries its reason — `[⚠VERIFY — client permission owed]`. §5.1.1 held eight; the gate reported **zero**. Lint only checks frozen artefacts, so the count was invisible until after freeze | drafting §5.1.1 against real evidence gaps, then reading the gate output | `section_contract.VERIFY_RE` matches any form; both strict profiles use it; new `rule_verify_open_in_draft` counts markers while drafting (warn) and errors when the status claims shippable |
| 2 | **A figure caption shipped our internal filenames into the tender.** The section template's own caption ended `Source: F-01_x.html; editable one-slide F-01_x.pptx…`. The strip removes blockquotes, the traceability line and the review log — never a caption — so both filenames printed on the rendered A4 page | rendering §5.1.3 to PDF with the bid strip and reading the page | caption is client-facing text only; the pointer moves to a `**Figure source.**` line that the strip removes; template, contract doc and both drafted sections updated; new lint warning `figure-source-in-caption` |
| 3 | **A ten-row research log tracked as zero entities.** `change_impact.py` read a register's row id only as a bare integer (`\| 1 \|`), so a log written the way the rest of the pack writes ids (`BR-001`) yielded an empty entity set — silently. A changed research claim invalidated nothing. The section side had the mirror defect: only `log #3` counted as a citation, not `BR-003` | checkpointing after writing the log; `entities.research == 0` while requirements=69, assets=16, scope=17 | `numbered_row_id()` accepts `BR-001`/`br-1`/`#3`/`3`; section dependencies also parse inline `BR-nnn`; the log template now plants `BR-nnn` ids |
| 4 | **The change-impact gate invented review rounds that never ran.** A `reviewed-r1` section whose figure changed was pushed to **`revise-r2`** and given a review-log row labelled **`R3`**. Combined with bug 5, that fabricated round then became the "latest verdict" every downstream gate trusts | running `--apply` on the real repo and diffing the section | `sc.revise_status_for()` sends a section back to the round it actually reached (`reviewed-r1` → `revise-r1`); the appended row is labelled `R1 (change-impact)` |
| 5 | **Lint could not read an iterated review round.** `rule_review_status` matched the round cell with `re.fullmatch(r"R\d+")`, so `R1 (2nd pass)` was ignored and the stale `revise` read as the latest verdict. The only way to satisfy the checker was to **overwrite** the first R1 row — destroying the audit trail that the contract's "one row per pass" rule exists to keep | recording R1 `revise` → fixes → R1 re-read `pass`, as the method prescribes | `sc.ROUND_LABEL_RE` accepts any `R<digits>…` label; the contract doc now states append-never-overwrite |
| 6 | **The gate nagged for work already done.** Editing a figure's HTML *and* regenerating both exports is the normal sequence; the report still said "regenerate PNG and editable PPTX" | re-running the scan after a legitimate figure fix | when source and both exports move together the impact drops to `info`: "confirm the regenerated PNG and PPTX match the new source" |
| 7 | **`--force` silently dropped every finding it overrode**, including the VERIFY count — and `--force` is the only way to measure a section's real page count before approval | measuring §5.1.3's submission page count mid-flight | forced builds re-run the gate and report each override as `FORCED past: …` |

Pattern worth naming, again: **every one of these needed the real sequence.** Bugs 1 and 2 only
appear once a section carries genuine evidence gaps and is actually rendered; bugs 3–5 only appear
once a review round iterates and a register is written by a human rather than by a template.

## Method gaps the flow exposed (fixed as method, not code)

1. **"Every requirement lands in exactly one section" does not survive a real tender.** Of 69 rows,
   **25 are not prose questions at all** — submission mechanics, the query deadline, and the terms
   accepted by tendering — and several are scored in *two* places (the roadmap under both
   Deliverables and Methodology). The outline template now carries an *Also answers* column and a
   **named-control table** (submission control sheet · clarification register · commercial sign-off ·
   partner-level contract acceptance). Coverage is now machine-checked
   (`rule_outline_covers_matrix`, error if a row appears nowhere); placement stays judgement.
2. **Nothing checked the pack's central promise.** "No number, credential or outcome enters the
   response without a `closed` row + citation" was prose only. `rule_research_rows_closed` now
   errors on a `BR-nnn` no log knows and warns when a section rests on an `open` row — which on
   this bid immediately separated the section that can ship (§5.1.3, every row closed) from the two
   that cannot (§5.1.1 rests on two open permission rows; §5.1.4 on an undated asset).
3. **The page budget only bit in one direction.** "The level of detail provided" is an explicit
   scoring dimension, so an unused half-budget on a 100+-mark criterion is marks left on the table.
   `section-underlength` now warns alongside `section-overlength` — and it fired on our own §5.1.1
   (1.7 of 4 A4) and §5.1.2 (0.9 of 3).
4. **You could not measure a submission page count until you no longer needed to.** The only build
   that measures the buyer's page count is the one the gate refuses until every section is approved;
   the `plain` internal copy measures a different document (it keeps the scaffolding). Both
   `eng-bid-respond` and `eng-render` now document the one honest way: render a single section with
   `--profile bid --force`, which reports what it overrode.
5. **A figure for an A4 document is not a slide.** `designing-figures` is slide-shaped by design
   (1920×1080, kicker, action title, source footer); dropped into A4 portrait its footer duplicates
   the markdown caption and its title competes with the section heading. The method now says which
   furniture to drop and that a 16:9 exhibit costs about a third of a page.
6. **The prerequisite refused the leg it gates.** `eng-bid-respond` demanded "a closed analysis
   (`compliance_matrix.md`)" and named an unmet mandatory row as the reason to go back — but rows
   close *because* the response answers them, and all 69 were `gap` on a fully-analysed bid.
   Reworded: settled means the go decision is taken, requirements are extracted and evidence is
   indexed; a closed matrix is the finish line, not the entry condition.
7. **R2 cannot be self-certified.** An agent that marks its own R2 has removed the gate, not passed
   it — so an agent-drafted section tops out at `reviewed-r1`. Now stated in the reference.

**Honest summary of the comparison.** The manual bid is a richer, more persuasive document that
breaches two page limits, carries at least one unevidenced performance claim, and states no
assumptions on a fixed-price engagement. The method's draft is compliant, measured, and fully
traceable — and thinner than it is allowed to be, with two of four sections honestly blocked on
inputs no writing can supply. The method now flags the thinness itself; closing the gap is a
drafting decision, not a tooling one.

## Second pass — run through the Skill tool, as a user (same day)

The first pass read each `SKILL.md` and ran its scripts directly. That tests the scripts, not the
path a user takes, so the flow was re-run by **invoking `engagement-os:eng-bid-respond` through the
Skill tool**. Four findings, none of which the first pass could have produced:

| # | Finding | Evidence |
|---|---|---|
| 8 | **The installed plugin was v1.14.0 — fifteen releases behind the repo.** The Skill tool resolved `engagement-os` through `~/.claude/plugins/.codepilot-links/engagement-os → cache/…/1.14.0`, so the body that loaded had no `eng-check`, `eng-render`, `eng-estimate`, `eng-index-assets` or `eng-propagate-change` **at all** — five of sixteen skills, including every gate. Its step 7 read "render to the mandated format (docx/pptx skills)", i.e. exactly the hand assembly `eng-render` exists to prevent: no strip, so scoring notes, the traceability line and the review log would have reached the evaluator. Every E2E to date had tested the git working copy, never the artefact a user gets | `claude plugin details` reported v1.14.0 (installed 2026-07-24); the loaded skill text matched 1.14.0, not the repo |
| 9 | **`claude plugin update engagement-os` fails on the bare name** — "Plugin not found". It needs the marketplace-qualified id, `engagement-os@engagement-os`. With that it updated 1.14.0 → 1.29.0, and the installed tree then matched the repo byte for byte (`diff -rq` clean) | CLI output both ways |
| 10 | **A mid-session update does not apply.** After the update the symlink still resolved to 1.14.0 ("Restart to apply changes"), so the fix a user pulls cannot be picked up in the session where they discover they need it | `readlink -f` after a successful update |
| 11 | **The change-impact row landed after rounds that never ran.** The section template planted empty `R2`/`R3` rows, so the appended `R1 (change-impact)` row sorted last — a log reading R1, R2, R3, then R1 again — and it swallowed the blank line before the closing prose | ran the real edit → invalidate → re-review loop on §5.1.3 |
| 12 | **The gate repeated its demand verbatim after being obeyed.** Edit → invalidate → re-review → re-render, exactly as the skill prescribes, and the report still said "set status to revise-r1 and re-review". Nothing distinguished "you have not responded" from "you have, and the outstanding step is the checkpoint" | same loop |

Fixes: the template stops planting rows for rounds that have not run (the log is append-only, and
the owed rounds are named in the prose below it); the engine inserts above the first unrun
placeholder and preserves the blank line; a re-review recorded after the baseline turns the demand
into `INFO … then checkpoint`. Review-log parsing moved into `section_contract.latest_verdict()` —
lint and the change gate now read the log through one parser instead of two.

**Release-process consequence, and it is the real lesson.** The pack's own rule is "test what the
user gets". Nothing in the release path did: no step reinstalls the local marketplace copy or
asserts that the Skill tool resolves the new version. Until that exists, an E2E on the working copy
can pass while every user is fifteen versions behind.
