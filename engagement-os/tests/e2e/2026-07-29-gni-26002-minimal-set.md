## Operator lessons (environmental, not pack defects)

- A headless LibreOffice that idles at **0% CPU** on a recalc is not computing — it is waiting
  on an invisible modal (here: the repair dialog for a truncated xlsx). Check CPU before
  waiting; check file integrity (`unzip -t`) before blaming the environment. `pkill` on a
  storing soffice is how the file got truncated in the first place.
- The xlsx was recoverable only because the workbook is a regenerable artefact — the seed
  markdown was intact. The doctrine (workbook is generated, seed/snapshot are text) is what
  made a 5-minute rebuild out of a lost model.
- LibreOffice user profile moved aside during diagnosis: `~/Library/Application Support/
  LibreOffice.bak-20260729` — harmless to delete; the fresh profile works.

## Non-defects observed (format rules the lint enforced on the operator)

- Coverage IDs must be 3 digits (`RC-001`): `RC-01` reads as zero real rows.
- Outline § column must be the buyer's own number (`§5.1.1`), not an invented row label
  (`V2.1`) — the section-file matcher keys on it.
- Req-ID ranges (`R-012–R-018`) do not expand in the outline — write every ID.
- A `[⚠VERIFY]` marker does not exempt a named best practice from method provenance
  (`solution-method-unsourced`); cite the primary URL or route to research.
- `--out` on render_document.py is a DIRECTORY.
