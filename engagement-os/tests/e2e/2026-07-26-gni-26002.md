# E2E — GNI 26-002 pursuit flow against the real tender pack (2026-07-26)

**What we did:** scaffolded a fresh pursuit repo (`~/working/gni-26002-v3`), dropped the REAL
GNI 26-002 tender pack (4 docs) and the REAL `_shared/` asset set (13 files) into it, and ran
the pursuit flow exactly as a user would: scan → ingest → analyze → index assets → lint.
Then compared the outputs against the original, manually-run GNI bid
(`~/working/gni/01_rfp/26-002/` — the bid we actually won).

**Why this pack:** it's the strongest ground truth we have — a won bid, run entirely by hand,
so every difference between its artefacts and the method's artefacts is either a method gap or
a lesson the manual bid learned the expensive way.

## Method-level improvements (fixed in v1.25.0)

1. **Template ↔ method mismatch.** `rfp_analysis.md.tmpl` had no clarification section, but
   method Step 6b derives clarification questions *inside* the analysis. The analyst agent had
   to invent §5b. Template now plants it.
2. **Mandatory/scored binary is strained** by scored criteria carrying minimum pass marks
   (the entire GNI Section 5: "50 of 100 to pass"). Matrix template now sanctions the
   convention: stays `D`, carries "(NN% pass mark applies)" in the requirement text.
3. **Scaffold missing two real categories.** The original GNI `_shared/` has `contracts_ref/`
   and `team_structure/`; the scaffold didn't, stranding exactly those assets at the root.
   Now planted by default.
4. **Citation order was unstated.** The ingest promised `## Page N` anchors, but pandoc
   headings aren't stable and page numbers rot on amendment. Method now says: native clause
   numbering first (`§2.1(f)` — buyer-checkable, amendment-stable), page anchors as fallback.

## What the index caught that the manual bid had no mechanism for

- **PTSB entity mismatch** (A-002/A-003): letterhead Deloitte Technology S.A. (Portugal), but
  R-017 requires the performing entity = the entity relied on. Flagged at indexing time with
  the R-014 letterhead-undertaking route. In the manual bid this lived in nobody's artefact.
- **Forest CV reference project 3 = 2022** — out of the 3-year window. The CV is otherwise
  submission-ready (already in Appendix 4 format).
- **A-005 quals pool: 9 project snapshots, zero per-project dates** — a backup pool that
  cannot back R-017 until dates are confirmed. `UNKNOWN` kept visible per the method's rule.
- **A whole mandatory cluster unevidenced**: R-025–R-029 security pass/fail (AUP, access
  audits, ISO 27001/SOC 2, DLP) — no security attestation held in `_shared/` at all. The
  gaps table routes it to the CISO office with "request at kickoff, long lead time".
